\# 04. Current-State Controls



\## Purpose

This document describes the baseline controls assumed to exist in the fictional environment before formal remediation.



\## Assumed Existing Controls



| Control Area | Assumed Current State |

|---|---|

| Identity and access | User accounts managed through central directory services; password policy exists |

| MFA | MFA enabled for some cloud services; not fully standardized |

| Endpoint protection | Endpoint security agent deployed on most endpoints |

| Email security | Basic spam and phishing filtering in place |

| Backups | Regular backups performed; restore testing inconsistent |

| Logging | Some system and security logs retained |

| Patch management | Basic patching process exists, but not consistently measured |

| Network security | Firewall and segmentation are present in limited form |

| Vendor management | Informal vendor review process exists |

| Incident response | A response plan exists in draft or basic form |

| Security awareness | Annual or periodic awareness training occurs |

| Access reviews | Ad hoc access review process exists |

| Data protection | Encryption may be present on some devices and services |

| Business continuity | Informal continuity planning exists |



\## Observations

The assumed current state reflects a small organization that has implemented some foundational controls but lacks maturity, consistency, and formal governance.



\## Key Gaps Suggested by the Current State

\- incomplete MFA coverage

\- inconsistent backup testing

\- limited logging and alerting maturity

\- weak access review discipline

\- limited formal documentation

\- unclear incident response roles and escalation paths
